\# Lab 5: Static Code Analysis



\## 1. Objective



To improve the quality, security, and style of the Hotel Booking System using Pylint, Bandit, and Flake8.



\## 2. Tools Used



\- \*\*Pylint:\*\* Checks code quality, naming conventions, unused variables, and programming practices.

\- \*\*Bandit:\*\* Detects common security vulnerabilities and unsafe coding patterns.

\- \*\*Flake8:\*\* Checks Python formatting and compliance with style guidelines.



\## 3. Issues Identified and Fixes Applied



| Issue | Type | Original line(s) | Description | Fix approach |

|---|---|---:|---|---|

| Mutable default argument | Bug | 14 | `booking\_log=\[]` could share the same list across calls. | Changed the default to `None` and initialized the list inside the function. |

| Broad exception handling | Code quality | 26 | A bare `except` hid errors when cancelling a booking. | Checked whether the room exists and removed the unnecessary exception handler. |

| Unsafe `eval()` | Security | 42 | Arbitrary expressions could execute as Python code. | Replaced `eval()` with a restricted arithmetic-expression evaluator using `ast`. |

| Weak MD5 hashing | Security | 47 | MD5 is unsuitable where stronger cryptographic hashing is needed. | Replaced MD5 with SHA-256. |

| Insecure random number generation | Security | 51 | `random.randint()` is not intended for security-sensitive random values. | Used `secrets.randbelow()` to generate booking references. |

| Shell command execution | Security | 58 | `os.system()` executed a shell command to display a message. | Removed shell execution and used `print()`. |

| Hardcoded secret | Security | 62 | A secret value was embedded directly in the source code. | Read the value from the `HOTEL\_ADMIN\_RESERVATION\_TOKEN` environment variable. |

| Function naming convention | Code quality | 14 | `bookRoom` did not follow PEP 8 snake\_case naming. | Renamed the function to `book\_room`. |

| Unused import and variables | Code quality/style | 6, 31, 41 | Unused imports and variables created unnecessary code. | Removed unused imports and variables. |

| Comparison and formatting issues | Style | 19, 32, 73 | The original code contained a long line, `== None`, and a missing final newline. | Reformatted the code, used `is None`, and ensured the file ends with a newline. |



\*Note: The line numbers refer to the original source file and may vary if the file is edited.\*

\## 5. Reflection



The handout asks students to reflect on their experience with static analysis, but it does not provide specific reflection questions. The following responses address the lab's stated learning outcomes.



\### 5.1 What is the purpose of static code analysis?



Static code analysis examines source code without executing it to identify potential bugs, security vulnerabilities, and style violations. It helps developers find problems early.



\### 5.2 What did Pylint, Bandit, and Flake8 contribute to this task?



Pylint helped identify code quality and naming issues. Bandit identified unsafe coding practices that could create security risks. Flake8 highlighted formatting and style violations.



\### 5.3 Why should high- and medium-severity findings be prioritized?



High- and medium-severity findings can present greater security or reliability risks. Addressing them first helps reduce important risks before spending time on lower-priority style issues.



\### 5.4 Why must the tools be rerun after fixing the code?



Rerunning the tools verifies whether the reported findings have been addressed and whether any new issues remain. In this lab, the final checks reported a Pylint score of 10.00/10, no Bandit findings, and no Flake8 violations.



\### 5.5 What did this lab teach me about code quality and maintainability?



The lab demonstrated that static analysis can identify unsafe functions, weak hashing, insecure randomness, hardcoded secrets, and inconsistent coding style. Fixing these issues makes the code easier to maintain and reduces potential security risks.



\## 6. Conclusion



The Hotel Booking System was analyzed using Pylint, Bandit, and Flake8. The identified code quality, security, and formatting issues were addressed, and the tools were rerun to verify the changes.
